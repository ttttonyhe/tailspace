Tailspace

Run Tailscale in Rootless Mode

Installing Tailscale on a remote Linux server normally requires root (admin) access via sudo, /dev/net/tun, and systemd. On a shared server such as an HPC login node, a Slurm cluster, a Kubernetes pod, or an unprivileged Docker container, you usually have none of those. Tailspace runs tailscaled in userspace networking mode with --tun=userspace-networking inside your home directory without root, so you can reach the server with SSH, VS Code Remote-SSH, or Jupyter from any device on your tailnet. 

$curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | bash
Prints a Tailscale login link and an SSH command once the server joins your tailnet.

Check shared cluster rules first. Tailspace keeps Tailscale running in the background, and Tailscale SSH skips the cluster's own two-factor check. Some clusters forbid one or both. Tailscale also expires device keys after 180 days by default, so disable key expiry in the admin console to keep the server connected for good.

What Tailspace does

Without root or systemd, Tailscale can't run as a system service, so Tailspace sets it up in userspace mode and looks after it with a small supervisor:

  • SSH and local web ports. Turns on Tailscale SSH on port 22, forwards OpenSSH on port 2222 when the server runs OpenSSH, and lets you reach local ports such as Jupyter on 8888 or TensorBoard on 6006 over your tailnet.
  • Crash, hang, and stuck-daemon recovery. Restarts tailscaled 5 seconds after a crash, probes state every 20 seconds so hangs restart after 3 missed checks, and restarts stuck connections once path probes confirm the network works.
  • Reboot recovery without systemd. Installs a user cron job on servers with cron and a sub-millisecond shell check in your startup files everywhere else.
  • Direct and HTTP proxy failover. Switches between a direct connection and your saved http:// proxy whenever either stops reaching Tailscale's coordination server.
  • Session-safe daily updates with rollback. Checks for new Tailscale releases daily, waits up to 3 days while sessions are open, and rolls back if a new version fails health checks.
  • Multi-user isolation on shared hosts. Locks down ~/.tailspace to mode 700, stores state per hostname under state/HOSTNAME/ for shared NFS home directories, and keeps unauthenticated SOCKS5 and HTTP proxies off.
  • Knows when to stop. Stops and explains why in tailspace status after an expired key, a bad auth key, or 5 failed runs in a row.

Everyday commands

tailspace status      # what it's doing, which path it's on, and why
tailspace stop        # stop Tailscale and keep it stopped across reboots
tailspace start       # start it again
tailspace restart     # restart Tailscale, even over Tailscale SSH
tailspace self-update # update Tailspace itself
tailspace uninstall   # log the server out and remove everything

Tailspace also installs a pre-wired tailscale command in ~/.local/bin that talks to your rootless socket, so tailscale status, tailscale ping, and tailscale nc work with no extra flags.

Requirements

  • Linux 3.2 or newer, including CentOS 7, on x86_64, arm64, 32-bit ARM, 386, or riscv64.
  • bash 4.2 or newer, plus curl or wget.
  • awk, flock, setsid, and timeout, which almost every distribution includes.
  • A normal, non-root Linux account.

Frequently asked questions

Can I install and run Tailscale without root or sudo?

Yes. Tailspace downloads Tailscale's official static binaries into ~/.tailspace/bin and runs tailscaled --tun=userspace-networking. It never opens /dev/net/tun and doesn't ask for sudo, CAP_NET_ADMIN, or systemd.

Does Tailspace survive crashes and server reboots without systemd?

Yes. A user-level supervisor restarts tailscaled 5 seconds after a crash and checks it every 20 seconds so hangs restart after 3 missed checks. After a reboot, a user cron job starts Tailspace right away where cron runs, and a 0.9 ms shell check brings it back on your next login everywhere else.

Can I use VS Code Remote-SSH, Cursor, and Jupyter over rootless Tailscale?

Yes. Tailspace turns on Tailscale SSH on port 22 and forwards OpenSSH on port 2222 when the server runs OpenSSH, so VS Code Remote-SSH, Cursor, scp, and rsync connect to your server's tailnet name. Local web servers such as Jupyter on port 8888 or TensorBoard on port 6006 work at http://hostname:8888.

What happens if my server is behind an HTTP proxy or firewall?

Export https_proxy=http://HOST:PORT before installing. Tailspace saves that proxy, switches between the direct path and the proxy path when either fails, and switches back once direct access stays healthy. See the HTTP proxy failover guide.

Is Tailspace safe on a shared university or lab server?

Tailscale runs only as your user account, ~/.tailspace uses mode 700, and Tailscale's unauthenticated SOCKS5 and HTTP proxies stay off so other users on the host can't reach your tailnet. Pass keys with TS_AUTHKEY=file:/path/to/key so secrets never appear in /proc/*/cmdline.

How much CPU and memory does Tailspace use?

On a Kubernetes pod with 124 usable cores and 1,435 visible processes running Tailscale 1.104.7, Tailspace adds 0.9 ms to each new shell and uses 0.14% of one CPU core and 30 MB of memory at idle. Userspace networking moved about 10 Gbit/s in a local loopback test.
