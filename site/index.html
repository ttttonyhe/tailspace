Run Tailscale in Rootless Mode

Installing Tailscale on a remote Linux server normally requires root (admin) access, /dev/net/tun, and systemd. Tailspace runs and supervises tailscaled in userspace mode inside your home directory without root, so you can SSH into shared HPC nodes, Slurm clusters, or Kubernetes pods from any device on your tailnet.

Install

One command on the server

Open the login link it prints, then run the SSH command it gives you from any device on your tailnet.

$curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | bash
Read reference
Auth key, HTTP proxy, or custom install path

Headless install with an auth key stored in a mode 0600 file:

curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | TS_AUTHKEY=file:/path/to/key bash -s -- install --hostname lab-07

Server behind an HTTP proxy:

export https_proxy=http://127.0.0.1:7890
curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | bash

Home directory mounted noexec or blocking file locks:

curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | TAILSPACE_PREFIX=/scratch/$USER/tailspace bash

Shared clusters. Check cluster rules before installing, since Tailspace runs in the background and Tailscale SSH skips cluster two-factor checks. Disable 180-day key expiry in the admin console to stay connected.

What it does

Keeps rootless Tailscale online

  • SSH and local portsTailscale SSH on port 22, OpenSSH on port 2222, and direct access to localhost ports like Jupyter.
  • Crashes and rebootsRestarts tailscaled on crashes or hangs, and recovers after reboots via cron or a 0.9 ms shell check.
  • HTTP proxy failoverSwitches between direct and your saved HTTP proxy whenever either stops reaching Tailscale.
  • Safe daily updatesUpdates daily, waits up to 3 days for open sessions to close, and rolls back broken releases.
  • Shared-host isolationLocks ~/.tailspace to mode 700, splits NFS hosts under state/HOSTNAME/, and keeps local proxies off.
Usage

Everyday commands

tailspace status      # what it's doing, and why
tailspace stop        # stop it, and keep it stopped across reboots
tailspace start       # start it again
tailspace self-update # update Tailspace itself
tailspace uninstall   # log the server out and remove everything

Runs on Linux 3.2 or newer, including CentOS 7, with bash 4.2+ and a regular user account.

FAQ

Frequently asked questions

Can I install and run Tailscale without root or sudo?

Yes. Tailspace downloads Tailscale's official static binaries into ~/.tailspace/bin and runs tailscaled --tun=userspace-networking. It never opens /dev/net/tun and doesn't ask for sudo, CAP_NET_ADMIN, or systemd.

Does Tailspace survive crashes and server reboots without systemd?

Yes. A user-level supervisor restarts tailscaled 5 seconds after a crash and checks it every 20 seconds so hangs restart after 3 missed checks. After a reboot, a user cron job starts Tailspace right away where cron runs, and a 0.9 ms shell check brings it back on your next login everywhere else.

Can I use VS Code Remote-SSH, Cursor, and Jupyter over rootless Tailscale?

Yes. Tailspace turns on Tailscale SSH on port 22 and forwards OpenSSH on port 2222 when the server runs OpenSSH, so VS Code Remote-SSH, Cursor, scp, and rsync connect to your server's tailnet name. Local web servers such as Jupyter on port 8888 or TensorBoard on port 6006 work at http://hostname:8888.

What happens if my server is behind an HTTP proxy or firewall?

Export https_proxy=http://HOST:PORT before installing. Tailspace saves that proxy, switches between the direct path and the proxy path when either fails, and switches back once direct access stays healthy. See the HTTP proxy failover guide.

How much CPU and memory does Tailspace use?

On a Kubernetes pod with 124 usable cores and 1,435 visible processes running Tailscale 1.104.7, Tailspace adds 0.9 ms to each new shell and uses 0.14% of one CPU core and 30 MB of memory at idle. Userspace networking moved about 10 Gbit/s in a local loopback test.
