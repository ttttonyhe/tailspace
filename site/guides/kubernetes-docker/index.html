Tailspace / Kubernetes & Docker

Tailscale in Kubernetes pods and unprivileged Docker containers

Locked-down GPU pods, managed Kubernetes dev environments, and unprivileged Docker containers strip out CAP_NET_ADMIN, hide /dev/net/tun, and run without systemd or cron. Tailspace installs into your home directory with one command and gives you Tailscale SSH, VS Code Remote-SSH, and localhost port access without changing pod specs or container privileges.

Install

No CAP_NET_ADMIN, no /dev/net/tun

Standard Tailscale container guides ask for CAP_NET_ADMIN and a host mount for /dev/net/tun. Tailspace skips kernel networking by running tailscaled --tun=userspace-networking:

curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | bash

For non-interactive pod entrypoints or recreated pods, mount a reusable auth key as a 0600 Kubernetes Secret and pass it through TS_AUTHKEY:

curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | \
  TS_AUTHKEY=file:/var/run/secrets/tailscale/authkey bash -s -- install --hostname gpu-pod-01
Container behavior

How Tailspace handles container environments

  • UDP GSO offUDP GSO batches packets in a way that cripples throughput on some container virtual NICs; see tailscale#20858. Tailspace detects container cgroup namespaces and turns UDP GSO off.
  • No systemd or cronTreats un-reaped zombies as gone through /proc, and skips adding a crontab when no cron daemon runs on the container's own root filesystem, even under hostPID: true.
  • Shared PID namespaceNever runs ps or pgrep. Identifies its own tailscaled and lock holders through /proc/PID/fd and --statedir, leaving other pods untouched.
  • Pod restart detectionTracks each container's root overlay identity alongside the kernel boot ID. A pod restart with the same hostname and persistent $HOME counts as a reboot and clears earlier give-ups on the next kubectl exec.
  • High-core worker capCaps GOMAXPROCS=8 when more than 8 worker cores are visible, cutting idle Tailscale threads from 57 to 14 and probe CPU time from 57 ms to 15 ms.

FAQ

Frequently asked questions

Does Tailspace need CAP_NET_ADMIN or /dev/net/tun in Kubernetes or Docker?

No. Tailspace launches tailscaled --tun=userspace-networking, so it never accesses /dev/net/tun and needs no Linux capabilities or privileged container settings.

How does Tailspace recover when a container has no systemd or cron?

Tailspace adds a 0.9 ms background shell check to your startup files, such as ~/.bashrc and ~/.zshrc. After a pod restarts, the next kubectl exec or shell login starts the supervisor and tailscaled again.

What if a Kubernetes Deployment assigns a new pod hostname on recreate?

Tailspace names each state directory after the container's OS hostname under state/HOSTNAME/, so a pod recreated with a new hostname counts as a new server. Use a StatefulSet or fixed spec.hostname to keep that state directory across recreates, or run tailspace install again with a reusable auth key.
