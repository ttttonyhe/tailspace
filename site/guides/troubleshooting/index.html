Tailspace / Troubleshooting

Troubleshooting and common errors

Start with tailspace status and check tailspace logs -f for details. The sections below map the most common rootless Tailscale errors and stop states to exact fixes.

Errors

Common errors and fixes

  • failed to open /dev/net/tunStandard Tailscale installs require root and CAP_NET_ADMIN to open a kernel TUN device. Install Tailspace instead; it always launches tailscaled --tun=userspace-networking and never touches /dev/net/tun.
  • System has not been booted with systemdOccurs when running systemctl --user in containers or older hosts. Tailspace doesn't use systemd; its supervisor runs as a plain user process and recovers via cron and your shell check.
  • Can't reach controlplane.tailscale.comThe server needs an HTTP proxy. Export https_proxy=http://HOST:PORT before installing, or run tailspace set --proxy http://HOST:PORT. See the proxy guide.
  • Tailscale SSH refuses loginVerify your tailnet policy has an ssh rule with autogroup:nonroot as in examples/policy.hujson, and connect as the account that installed Tailspace.
  • Nothing runs after a rebootThe server has no cron daemon and nobody has opened a shell since the reboot. Log in once through the cluster's normal SSH or kubectl exec so the shell check starts Tailspace.
  • tailscaled won't run / noexecYour home directory doesn't allow running binaries, blocks flock, or makes socket paths too long. Reinstall to a short local path with TAILSPACE_PREFIX=/scratch/$USER/tailspace.
  • Slow transfers or laggy typingRun tailspace status. If an active device shows relay, traffic is using a distant DERP server. Set up a custom DERP server or peer relay.
Stop states

When Tailspace gives up

Tailspace stops instead of retrying forever when human action is needed. Here is every stop text tailspace status prints:

Status saysWhat happenedWhat to do
stopped with tailspace stopYou stopped TailspaceRun tailspace start
this server must log in againIts key expired, or someone removed it from your tailnetRun tailspace install again
adding this server to your tailnet failedThe auth key expired or ran out, or its tag isn't in your policyRun tailspace install with a valid auth key
Tailscale failed 5 times in a rowTailscale crashed, hung, or stayed offline while the network worked 5 times in a rowCheck tailspace logs, then run tailspace start
no reason was savedThe disk was full when Tailspace stopped, so it couldn't write whyFree space, then run tailspace start

Give-ups for this server must log in again or 5 failures hold only for the current boot. On a remote server whose 180-day key expired, choose Temporarily extend key on Tailscale's Machines page, disable key expiry within 30 minutes, and reboot the server so cron or the next login brings it back online.

FAQ

Frequently asked questions

How do I recover a remote Tailspace server whose 180-day key expired?

In Tailscale's admin console on the Machines page, choose Temporarily extend key and disable key expiry within 30 minutes. Then reboot the server or wait for its next reboot; Tailspace clears login give-ups across reboots and reconnects via cron or the next shell login.

Why does install say file locks don't work or a path is too long?

Some network filesystems don't grant exclusive flock locks or place $HOME under a deep path that exceeds Unix socket limits. Install to a short local path with TAILSPACE_PREFIX=/tmp/$USER/ts or /scratch/$USER/tailspace.

Why did Tailspace stop after 5 failures in a row?

Tailspace stops retrying after 5 consecutive runs where tailscaled crashes, hangs, or stays stuck offline while the network works. Inspect tailspace logs, fix the underlying issue, and run tailspace start.
