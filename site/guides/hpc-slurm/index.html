Run Tailscale on HPC and Slurm clusters without root

University and lab clusters rarely give users sudo, /dev/net/tun, or systemd --user lingering, and many still run CentOS 7 or RHEL with shared NFS home directories. Tailspace installs tailscaled in userspace networking mode under your account, supervises it across crashes and reboots, and lets you reach SSH, VS Code Remote-SSH, and Jupyter over your tailnet.

Check your cluster policy before installing. Tailspace keeps a background process running, and Tailscale SSH skips the cluster's own two-factor check. Some HPC centers forbid persistent daemons on login nodes or external tunnels. Verify your cluster's rules first.

Install

Login nodes and transient Slurm jobs

For an interactive login on a cluster node, run the default installer:

curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | bash

For scripted setup or transient Slurm compute nodes, save a reusable auth key tagged tag:server in a 0600 file and pass it through TS_AUTHKEY so other users on the cluster can't see it in /proc/*/cmdline. Make the key ephemeral too if you want Slurm nodes removed once jobs finish:

chmod 600 ~/.ts-key
curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | \
  TS_AUTHKEY=file:$HOME/.ts-key bash -s -- install --hostname hpc-login-01

Tagged devices have key expiry off by default in Tailscale. Copy examples/policy.hujson into your tailnet policy so tagged cluster nodes accept Tailscale SSH from your devices without being able to open connections back to your laptop. For IDE and port setup, see the VS Code and Jupyter guide.

Shared NFS

Multiple nodes sharing one home directory

Most HPC clusters mount one NFS $HOME across every login and compute node. Running a single-state tailscaled script on two nodes corrupts the state file or makes nodes fight over one device identity.

Tailspace keeps each host's runtime data under ~/.tailspace/state/HOSTNAME/ while sharing bin/, config, and the shell check across nodes:

~/.tailspace/
  bin/                  shared tailscale and tailscaled binaries
  config                shared settings
  state/login-01/       state, lock, and log for login-01
  state/login-02/       state, lock, and log for login-02

Run tailspace install once on each node you want on your tailnet. Running tailspace uninstall on one node removes only that host's state directory and keeps the shared binaries for the other nodes.

Scratch & CentOS 7

noexec home directories and older kernels

If $HOME is mounted noexec, blocks flock, or creates Unix socket paths that are too long, install to a local scratch path with TAILSPACE_PREFIX:

curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | \
  TAILSPACE_PREFIX=/scratch/$USER/tailspace bash
  • CentOS 7 and RHELSupports Linux 3.2+, bash 4.2+, and util-linux 2.23+. CI runs the unit, watcher, and supervisor tests on bash 4.2 built from source.
  • High-core login nodesSets GOMAXPROCS=8 when more than 8 cores are available, cutting a 124-core pod from 57 threads to 14 and probe CPU time from 57 ms to 15 ms, plus TS_PORTLIST=false.
  • Multi-user safetyLocks ~/.tailspace to mode 700, tracks processes through your own /proc descriptors, and keeps unauthenticated SOCKS5 and HTTP proxies off.
FAQ

Frequently asked questions

Can multiple HPC nodes share the same NFS home directory with Tailspace?

Yes. Each server keeps its own state, lock, and log under ~/.tailspace/state/HOSTNAME/, so multiple nodes sharing an NFS home directory share one installation while joining your tailnet as separate devices.

What if my HPC home directory is mounted noexec or breaks flock?

Set TAILSPACE_PREFIX=/scratch/$USER/tailspace, or another short path on a local disk, during install. Later tailspace commands find that location on their own.

Does Tailspace work on older HPC clusters running CentOS 7?

Yes. Tailspace supports Linux 3.2 and newer, bash 4.2, and util-linux 2.23, and CI runs the unit, watcher, and supervisor tests on bash 4.2.
