Tailspace / VS Code & Jupyter

VS Code Remote-SSH, Cursor, and Jupyter without root

Once Tailspace joins a shared Linux server, HPC node, or Kubernetes pod to your tailnet, your laptop reaches SSH, editors, and local web UIs without a VPN, bastion jump host, VS Code Tunnel, or kubectl port-forward.

SSH ports

Port 22 Tailscale SSH and port 2222 OpenSSH

Tailspace turns on Tailscale SSH on port 22. If the server also runs OpenSSH and none of your own processes holds 127.0.0.1:2222, Tailspace makes OpenSSH available on port 2222:

  • Port 22 (Tailscale SSH)Authenticates with your Tailscale identity instead of SSH keys. Tailscale knows which device connected. Change "check" to "accept" in your policy's ssh rule to skip Tailscale's 12-hour browser re-check.
  • Port 2222 (OpenSSH)Works with your existing SSH keys, agent forwarding, and ~/.ssh/config. Note that OpenSSH sees these connections arriving from 127.0.0.1, so from= limits in authorized_keys can't tell client devices apart.
Editors

VS Code Remote-SSH and Cursor config

Add the server to ~/.ssh/config on your laptop, using port 22 for Tailscale SSH or port 2222 for OpenSSH:

Host lab-07
  HostName lab-07
  User you
  Port 22

Open Remote-SSH in VS Code or Cursor and connect to lab-07. To turn Tailscale SSH off and hand port 22 back to OpenSSH, run tailspace set --no-ssh on the server.

Web UIs

Jupyter, TensorBoard, and localhost ports

In userspace mode, every port other than 22, 2222, and any tailscale serve port forwards straight to 127.0.0.1 on the server. Start Jupyter on port 8888 or TensorBoard on port 6006 and open it in your laptop browser with no ssh -L tunnel:

jupyter lab --no-browser --port=8888
# Open http://lab-07:8888 from any device on your tailnet

Because restarting tailscaled cuts connections over Tailscale, Tailspace delays daily updates and direct failbacks up to 3 days while SSH sessions or connections to 127.0.0.1 or ::1 stay open. Still run long training jobs inside tmux or screen.

Outbound

Connecting from the server with tailscale nc

Without root there is no kernel tailscale0 interface, so programs on the server reach other tailnet devices through tailscale nc. Add this once to ~/.ssh/config on the server:

Host lab-01
  User you
  Port 2222
  ProxyCommand tailscale nc %h %p

Then ssh lab-01, scp, rsync, and git reach other Tailspace servers by name. If servers are tagged with tag:server, uncomment the tag:server to tag:server grant in examples/policy.hujson. Tailspace leaves Tailscale's unauthenticated SOCKS5 and HTTP proxies off so other users on a shared server can't use your tailnet.

FAQ

Frequently asked questions

Why does Tailscale SSH ask me to log in in the browser every 12 hours?

Tailscale's default SSH policy uses check mode, which re-authenticates every 12 hours. Change "check" to "accept" in your policy's ssh rule, as examples/policy.hujson does for tag:server.

Can I run curl or ping from a rootless Tailspace server to another tailnet device?

Standard ping and programs that don't support tailscale nc can't reach tailnet addresses without a kernel TUN interface, though tailscale ping HOST works and ssh, scp, rsync, and git work through ProxyCommand tailscale nc %h %p.

Will an automatic Tailscale update drop my VS Code Remote-SSH session?

No. Tailspace checks for active SSH sessions, connections forwarded to 127.0.0.1 or ::1, and LocalAPI clients, holding daily updates for up to 3 days until sessions close.
