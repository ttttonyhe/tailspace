Tailspace

非 Root 身份运行 Tailscale

在远程 Linux 服务器上常规安装 Tailscale 需要 root（管理员）权限、sudo、/dev/net/tun 和 systemd。在 HPC 登录节点、Slurm 集群、Kubernetes Pod 或无特权 Docker 容器这类共享服务器上，这些条件通常都没有。Tailspace 会在你的家目录里以 userspace 网络模式和 --tun=userspace-networking 免 root 运行 tailscaled，让你通过 SSH、VS Code Remote-SSH 或 Jupyter 从 tailnet 里的任何设备连上服务器。 

$curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | bash
运行后打开打印出的登录链接，完成后会给出一条直接可用的 SSH 命令。

共享集群请先查看规定。 Tailspace 会让 Tailscale 一直在后台运行，Tailscale SSH 也会绕过集群自己的两步验证，有些集群禁止其中一项或两项。另外，Tailscale 的设备密钥默认 180 天后过期，想长期保持在线请在管理后台关闭密钥过期。

它会做什么

没有 root 或 systemd，Tailscale 没法作为系统服务运行，所以由 Tailspace 以 userspace 模式装好并用一个小监管进程替你照看：

  • SSH 与本地端口。 在 22 端口开启 Tailscale SSH，在服务器运行 OpenSSH 时把它转发到 2222 端口，并让你通过 tailnet 访问 8888 端口的 Jupyter 或 6006 端口的 TensorBoard。
  • 崩溃、无响应与卡死恢复。 tailscaled 崩溃 5 秒后重启 Tailscale，每 20 秒探测一次状态并在连续 3 次无响应后重启 Tailscale，网络正常却持续离线时也会重启它。
  • 免 systemd 的服务器重启恢复。 有 cron 的服务器上添加用户 cron 任务，其余服务器上在 shell 启动文件里加一段耗时不到 1 毫秒的 shell 检查。
  • 直连与 HTTP 代理切换。 直连路径和已保存的 http:// 代理路径哪条断了就切到另一条，直连稳定后再等会话结束切回。
  • 不中断会话的每日更新与回滚。 每天检查新版 Tailscale，有活动会话时最多等待 3 天，新版本未通过健康检查就回滚。
  • 共享服务器隔离与 NFS 多机共用。 ~/.tailspace 权限锁定为 700，关闭无密码的 SOCKS5 与 HTTP 代理，每台机器的状态按主机名存放在 state/HOSTNAME/。
  • 知道何时停止。 密钥过期、auth key 无效或连续失败 5 次时会停下，并在 tailspace status 里说明原因，不无休止重试。

实测资源占用

在一台有 124 个可用核心和 1,435 个可见进程、运行 Tailscale 1.104.7 的 Kubernetes Pod 上测得：

每个新 shell 增加耗时
0.9ms
空闲单核 CPU 占用
0.14%
空闲内存
30MB
userspace 本机吞吐
~10Gbit/s

可用核心超过 8 个时，Tailspace 会设 GOMAXPROCS=8。在这台 124 核 Pod 上，这把 Tailscale 的线程数从 57 降到 14，每次状态检查的 CPU 时间从 57 毫秒降到 15 毫秒。

常用命令

tailspace status      # 查看运行状态、当前路径和近期事件
tailspace stop        # 停止，服务器重启后也保持停止
tailspace start       # 重新启动
tailspace restart     # 重启 Tailscale，通过 Tailscale SSH 运行也能完成
tailspace self-update # 更新 Tailspace 自身
tailspace uninstall   # 登出 tailnet 并清理文件、shell 检查与 cron 任务

Tailspace 还会在 ~/.local/bin 安装配置好的 tailscale 命令，直接对接当前用户的 socket，运行 tailscale status、tailscale ping 或 tailscale nc 不需要额外参数。

系统要求

  • Linux 3.2 或更新版本，包括 CentOS 7，架构为 x86_64、arm64、32 位 ARM、386 或 riscv64。
  • bash 4.2 或更新版本，以及 curl 或 wget。
  • awk、flock、setsid 和 timeout，几乎所有发行版都自带。
  • 服务器上的一个普通非 root 账号。

常见问题

没有 root 或 sudo 权限也能安装运行 Tailscale 吗？

可以。Tailspace 从官方源下载静态二进制文件到 ~/.tailspace/bin，并以 tailscaled --tun=userspace-networking 运行，不打开 /dev/net/tun，也不需要 sudo、CAP_NET_ADMIN 或 systemd。

没有 systemd，Tailscale 崩溃或服务器重启后能恢复吗？

可以。用户态监管进程在崩溃 5 秒后重启 Tailscale，并每 20 秒检查一次状态，连续 3 次无响应就重启 Tailscale。服务器重启后，有 cron 的机器由用户 crontab 立即启动，其余机器在你下次登录时由 0.9 毫秒的 shell 检查拉起。

免 root 的 Tailscale 支持 VS Code Remote-SSH、Cursor 和 Jupyter 吗？

支持。Tailspace 在 22 端口开启 Tailscale SSH，并在服务器运行 OpenSSH 时把它转发到 2222 端口，VS Code Remote-SSH、Cursor、scp 和 rsync 可以直接连上服务器的 tailnet 名字。8888 端口的 Jupyter 或 6006 端口的 TensorBoard 访问 http://主机名:8888 就能打开。

服务器在 HTTP 代理或防火墙后面怎么办？

首次安装前执行 export https_proxy=http://HOST:PORT。Tailspace 会保存这个代理，在直连路径和代理路径哪条失效时切到另一条，直连稳定后再切回。详见 HTTP 代理切换指南。

在高校或实验室共享服务器上使用安全吗？

Tailscale 只以你的普通账号运行，~/.tailspace 权限为 700，并且保持无密码的 SOCKS5 与 HTTP 代理关闭，同机其他用户进不了你的 tailnet。用 TS_AUTHKEY=file:/path/to/key 传入密钥，可避免密钥出现在 /proc/*/cmdline。

Tailspace 的 CPU 和内存开销有多大？

在有 124 个可用核心和 1,435 个可见进程、运行 Tailscale 1.104.7 的 Kubernetes Pod 上测得，每个新 shell 增加 0.9 毫秒，空闲时占一个 CPU 核心的 0.14% 和 30 MB 内存，userspace 本机回环吞吐约 10 Gbit/s。
