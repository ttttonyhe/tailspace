非 Root 身份运行 Tailscale

在远程 Linux 服务器上常规安装 Tailscale 需要 root（管理员）权限、sudo、/dev/net/tun 和 systemd。在 HPC 登录节点、Slurm 集群、Kubernetes Pod 或无特权 Docker 容器这类共享服务器上，这些条件通常都没有。

Tailspace 会在你的家目录里以 userspace 网络模式和 --tun=userspace-networking 免 root 运行并监管 tailscaled，让你通过 SSH、VS Code Remote-SSH 或 Jupyter 从 tailnet 里的任何设备连上服务器。

安装

单个 bash 脚本，无需 sudo

在远程服务器上运行安装命令。它会把官方静态二进制文件装到 ~/.tailspace，启动监管进程，并打印登录链接和可直接使用的 SSH 命令。

# 运行后打开登录链接，完成后打印一条可直接使用的 SSH 命令
$curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | bash
查看完整命令参考

共享集群请先查看规定。 Tailspace 会让 Tailscale 一直在后台运行，Tailscale SSH 也会绕过集群自己的两步验证，有些集群禁止其中一项或两项。另外，Tailscale 设备密钥默认 180 天后过期，想长期在线请在管理后台关闭密钥过期。

监管进程

没有 systemd，依然保持在线

没有 root 或 systemd，Tailscale 没法作为系统服务运行。Tailspace 在 tailscaled 旁边运行一个轻量监管进程：

  • SSH 与本地端口 在 22 端口开启 Tailscale SSH，在服务器运行 OpenSSH 时把它转发到 2222 端口，并让你通过 tailnet 访问 8888 端口的 Jupyter 或 6006 端口的 TensorBoard。见 VS Code 与 Jupyter 指南。
  • 崩溃与卡死恢复 tailscaled 崩溃 5 秒后重启 Tailscale，每 20 秒探测一次状态并在连续 3 次无响应后重启 Tailscale，网络正常却持续离线时也会重启它。
  • 服务器重启恢复 有 cron 守护进程的服务器上添加用户 cron 任务，其余服务器上在 shell 启动文件里写入耗时 0.9 毫秒的 shell 检查，下次登录即拉起。
  • 不中断会话的更新 每天检查 Tailscale 新版本，有活动会话时最多等待 3 天，新版本未通过 2 分钟上线检查和 30 秒稳定期就回滚。
  • 共享主机隔离 ~/.tailspace 权限锁定为 700，按主机名在 state/HOSTNAME/ 下保存状态支持多机共享 NFS 家目录，并关闭无密码 SOCKS5 与 HTTP 代理。
  • 明确的停止原因 密钥过期、auth key 无效或连续失败 5 次时会停下，并在 tailspace status 里说明原因，不无休止重试。
故障切换

直连路径与 HTTP 代理切换

Tailscale 只在启动时读取一次代理设置。服务器配有 HTTP 代理时，监管进程用 tailscale debug ts2021 探测直连路径和代理路径，哪条断了就切到另一条；从代理切回直连时会等到活动会话结束，累计最多等 3 天。详见 HTTP 代理与中继指南。

命令行

常用命令与系统要求

Tailspace 还会在 ~/.local/bin 安装配置好的 tailscale 命令，直接对接你的用户 socket，无需额外参数：

tailspace status      # 查看运行状态、当前路径和近期事件
tailspace stop        # 停止，服务器重启后也保持停止
tailspace start       # 重新启动
tailspace restart     # 重启 Tailscale，通过 Tailscale SSH 运行也能完成
tailspace self-update # 更新 Tailspace 自身
tailspace uninstall   # 登出 tailnet 并清理文件、shell 检查与 cron 任务

在一台有 124 个可用核心和 1,435 个可见进程、运行 Tailscale 1.104.7 的 Kubernetes Pod 上测得，设 GOMAXPROCS=8 把线程从 57 降到 14，每次状态检查的 CPU 时间从 57 毫秒降到 15 毫秒。系统要求：Linux 3.2+（含 CentOS 7）、bash 4.2+、curl 或 wget，以及 awk、flock、setsid、timeout。详见命令与选项参考。

常见问题

常见问题

没有 root 或 sudo 权限也能安装运行 Tailscale 吗？

可以。Tailspace 从官方源下载静态二进制文件到 ~/.tailspace/bin，并以 tailscaled --tun=userspace-networking 运行，不打开 /dev/net/tun，也不需要 sudo、CAP_NET_ADMIN 或 systemd。

没有 systemd，Tailscale 崩溃或服务器重启后能恢复吗？

可以。用户态监管进程在崩溃 5 秒后重启 Tailscale，并每 20 秒检查一次状态，连续 3 次无响应就重启 Tailscale。服务器重启后，有 cron 的机器由用户 crontab 立即启动，其余机器在你下次登录时由 0.9 毫秒的 shell 检查拉起。

免 root 的 Tailscale 支持 VS Code Remote-SSH、Cursor 和 Jupyter 吗？

支持。Tailspace 在 22 端口开启 Tailscale SSH，并在服务器运行 OpenSSH 时把它转发到 2222 端口，VS Code Remote-SSH、Cursor、scp 和 rsync 可以直接连上服务器的 tailnet 名字。8888 端口的 Jupyter 或 6006 端口的 TensorBoard 访问 http://主机名:8888 就能打开。

服务器在 HTTP 代理或防火墙后面怎么办？

首次安装前执行 export https_proxy=http://HOST:PORT。Tailspace 会保存这个代理，在直连路径和代理路径哪条失效时切到另一条，直连稳定后再切回。详见 HTTP 代理切换指南。

在高校或实验室共享服务器上使用安全吗？

Tailscale 只以你的普通账号运行，~/.tailspace 权限为 700，并且保持无密码的 SOCKS5 与 HTTP 代理关闭，同机其他用户进不了你的 tailnet。用 TS_AUTHKEY=file:/path/to/key 传入密钥，可避免密钥出现在 /proc/*/cmdline。

Tailspace 的 CPU 和内存开销有多大？

在有 124 个可用核心和 1,435 个可见进程、运行 Tailscale 1.104.7 的 Kubernetes Pod 上测得，每个新 shell 增加 0.9 毫秒，空闲时占一个 CPU 核心的 0.14% 和 30 MB 内存，userspace 本机回环吞吐约 10 Gbit/s。
