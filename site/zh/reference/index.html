命令、选项与配置参考

Tailspace 是一个装在 ~/.tailspace 的单文件 bash 脚本，并在 ~/.local/bin 链接了 tailspace 和 tailscale。下面列出全部命令、选项、环境变量、目录结构和 Tailscale 调整项，与 ADVANCED.zh-CN.md 保持一致。

命令

CLI 子命令

命令作用
tailspace install [选项]安装 Tailspace 并加入 tailnet，可安全重复运行并保留已保存设置。
tailspace status查看运行状态、当前路径、是否有等待中的更新以及近期事件。
tailspace start启动监管进程与 tailscaled。
tailspace stop停止 Tailscale 和监管进程，服务器重启后也保持停止。
tailspace restart重启 Tailscale，即使通过 Tailscale SSH 运行也能完成。
tailspace set [选项]不重装直接修改设置，例如 tailspace set --no-ssh。
tailspace update [版本]立即更新 Tailscale。传入版本号会固定该版本并关闭每日更新。
tailspace logs [-f]查看或持续跟踪 tailscaled.log，类似 tail -f。
tailspace self-update从仓库 main 分支下载并更新 Tailspace 自身。
tailspace uninstall登出 tailnet，停止 Tailspace，并删除文件、cron 任务与 shell 检查。
选项

install 与 set 选项

选项默认值含义
--authkey KEYauth key 或 file:PATH，仅限安装。建议用 TS_AUTHKEY 避开 /proc/*/cmdline。
--tags TAGS服务器标签如 tag:server，仅限安装。用 OAuth client secret 时必填。
--version VERSION最新版安装指定 Tailscale 版本并关闭每日更新，仅限安装。
--hostname NAME主机名服务器在你 tailnet 里的名字。
--proxy URL | nonehttps_proxy代理路径使用的 HTTP 代理或 none，只支持 http://。
--udp-port PORT0直连用的 UDP 端口，1024 到 65535，需要在防火墙放行时指定。
--[no-]autostart开管理服务器重启后恢复运行的 shell 检查和用户 cron 任务。
--[no-]auto-update开每日 Tailscale 更新，有会话时最多等 3 天，失败则回滚。
--[no-]ssh开22 端口 Tailscale SSH，2222 端口 OpenSSH。关闭后 22 端口通往 OpenSSH。
--[no-]log-upload开向 Tailscale 上传诊断日志，开启网络流日志的 tailnet 必须保持开启。

环境变量

  • TS_AUTHKEY等同于 --authkey，但密钥不出现在进程列表。配合 0600 文件使用 TS_AUTHKEY=file:/path/to/key 可同时避开 shell 历史。
  • TAILSPACE_PREFIX替代 ~/.tailspace 的安装路径，适合家目录挂载 noexec 或不支持文件锁时。后续命令会自己找到新位置。
文件

目录结构与共享家目录

~/.tailspace/
  tailspace           Tailspace 本身，shell 检查和 cron 任务运行这一份
  bin/                tailscale 和 tailscaled 程序
  bin.prev/           上一个版本的 Tailscale，用于回滚
  config              已保存的设置
  bad-version         更新后未通过健康检查的版本
  state/HOSTNAME/     属于某一台服务器的全部内容
    tailscaled.state  服务器在你 tailnet 里的身份
    tailscaled.log    日志，超过 10 MB 后重新开始
~/.local/bin/         tailspace 和 tailscale 命令

共用 NFS 家目录的节点共用一个 ~/.tailspace，按主机名在 state/HOSTNAME/ 下隔离状态。详见超算与 Slurm 指南。

调优

Tailspace 对 Tailscale 做的调整

调整原因
可用核心 > 8 时 GOMAXPROCS=8在 124 核 Pod 上把线程从 57 降到 14，状态检查 CPU 时间从 57 毫秒降到 15 毫秒。
TS_PORTLIST=false不再每秒扫描开放端口，这份列表只在管理后台显示。
TCP keepalive 60 秒后每 15 秒连向已消失设备的连接在几分钟内关闭，而不是两小时。
容器内关闭 UDP GSO避免容器虚拟网卡上的吞吐骤降，见 tailscale#20858。
GODEBUG=tlsmlkem=0防止中间网络丢弃 ML-KEM TLS 握手，见 tailscale#20777。

配合 examples/policy.hujson 定义 tag:server、放行 autogroup:nonroot 的 Tailscale SSH，并在 Tailscale 1.104+ 上开启 cache-network-maps。常见报错与停止状态见故障排查。

常见问题

常见问题

如何在不把 auth key 留在 shell 历史和 /proc 里的前提下安装？

把密钥存进权限为 0600 的文件，安装时传入 TS_AUTHKEY=file:/path/to/key。Tailspace 通过管道把密钥交给 tailscale up，不会出现在 /proc/*/cmdline。

如何固定某个 Tailscale 版本并关闭每日更新？

已安装的机器运行 tailspace update 1.104.6，或首次安装时传入 --version 1.104.6，两者都会安装该版本并关闭每日更新。

如何卸载 Tailspace？

运行 tailspace uninstall。它会让服务器登出 tailnet、停止监管进程和 tailscaled，并移除文件、shell 检查和用户 crontab；如果还有其他节点共用这个前缀，会保留它们需要的共享文件。
