Tailspace 与手动 tailscaled、systemd --user 对比

网上大多数无 root 运行 Tailscale 的教程，会让你下载静态压缩包后运行 nohup tailscaled --tun=userspace-networking &，或者写一个 ~/.config/systemd/user/ 服务。这套做法能撑过一个下午，但想让一台无 root 服务器稳定在线几个月，离不开监管进程。

功能对比

能力 手动 nohup tailscaled systemd --user 服务 Tailspace
免 root、sudo、/dev/net/tun 与 CAP_NET_ADMIN 支持 支持 支持
无需 systemd --user（容器、CentOS 7、未开启 linger） 支持 不支持 支持
崩溃、无响应与控制连接卡住时重启 Tailscale 不支持 仅在崩溃后重启 Tailscale 支持（20 秒探测，崩溃 5 秒后重启 Tailscale）
服务器重启后免 root 恢复 不支持 需管理员开启 linger cron 加 0.9 毫秒 shell 检查
直连与 HTTP 代理切换 不支持 不支持 支持，含退避防抖
每日更新、等待会话结束与故障回滚 不支持 不支持 支持（最多等 3 天）
多节点共用 NFS 家目录不冲突 需手工分目录 需手工分目录 内置（state/HOSTNAME/）
22 端口 Tailscale SSH 加 2222 端口 OpenSSH 需手工配置 需手工配置 内置
共享主机安全隔离（700 权限、不开放无密码代理） 容易配漏 容易配漏 内置
多核 Go 线程限制与容器 UDP GSO 关闭 不支持 不支持 GOMAXPROCS=8，容器内关 GSO

手动方案在实际使用中的 5 个问题

  • systemd --user 在容器里跑不起来，在共享机上退出登录就停。 Docker 和 Kubernetes 容器通常根本没有 systemd，运行会报 System has not been booted with systemd；即使在有 systemd 的机器上，没有管理员运行 loginctl enable-linger，退出 SSH 时用户服务就会停止。
  • 进程活着不等于网络还通。 只检查 PID 是否存在，发现不了 LocalAPI 无响应或控制连接卡住。Tailspace 每 20 秒轮询 tailscale status --json，离线时用 tailscale debug ts2021 做真实握手探测。
  • 手动升级会断掉当前 SSH 会话。 在 userspace 模式下，所有连接都活在 tailscaled 进程里，一重启 Tailscale 就会断线。Tailspace 会检测活动 SSH 会话、本地端口转发和 tailscale nc 客户端，最多等待 3 天再更新，并在新版本未通过 2 分钟上线检查和 30 秒稳定期时回滚。
  • 开启 --socks5-server=localhost:1055 会把 tailnet 暴露给同机邻居。 Tailscale 的本地 SOCKS5 和 HTTP 代理没有密码，共享服务器上的任何其他用户都能借 127.0.0.1:1055 访问你的个人设备。Tailspace 保持它们关闭，改用 ProxyCommand tailscale nc %h %p。
  • 多核机器上线程过多。 在 124 核 Pod 上不限制线程，tailscaled 会起 57 个线程并每秒扫描开放端口。Tailspace 设 GOMAXPROCS=8 与 TS_PORTLIST=false。

常见问题

为什么不直接用 nohup tailscaled --tun=userspace-networking 后台运行？

单纯的 nohup 进程崩溃或服务器重启后无法恢复，代理断了不会切换，不会自动更新，在共享 NFS 家目录的多台节点上还会互相争抢状态文件。

为什么不用 systemd --user 来托管无 root 的 Tailscale？

容器和 CentOS 7 通常缺少可用的用户级 systemd 总线，而现代发行版若未由 root 开启 linger，用户退出登录即停止服务。Tailspace 只要有 bash 4.2 就能运行。

我已经在手动跑 tailscaled 了，能直接切到 Tailspace 吗？

可以。停掉你手动启动的 tailscaled 进程，然后运行 Tailspace 的一行安装命令，它会装进 ~/.tailspace 并在 ~/.local/bin 放入配置好的 tailscale 命令。
