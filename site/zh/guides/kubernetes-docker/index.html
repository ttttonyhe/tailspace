Tailspace / Kubernetes 与容器

Kubernetes Pod 与无特权 Docker 容器免 root 运行 Tailscale

算力平台上的 GPU Pod、托管 Kubernetes 开发容器和无特权 Docker 容器，通常都没有 CAP_NET_ADMIN、/dev/net/tun、systemd 或 cron。Tailspace 不需要改 Pod YAML 或容器权限，一行命令装进家目录，就能用 Tailscale SSH、VS Code Remote-SSH 连进容器并访问本地端口。

无需任何容器特权

常规的 Tailscale 容器部署方案要求开启 CAP_NET_ADMIN 并挂载宿主机的 /dev/net/tun。在无法修改 SecurityContext 的受限容器里，Tailspace 通过 tailscaled --tun=userspace-networking 绕过内核网卡限制：

curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | bash

如果是无交互启动脚本或频繁重建的 Pod，把可重复 auth key 挂载成 0600 权限的 Kubernetes Secret 文件再通过 TS_AUTHKEY 传入：

curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | \
  TS_AUTHKEY=file:/var/run/secrets/tailscale/authkey bash -s -- install --hostname gpu-pod-01

Tailspace 在容器环境里的处理方式

  • 容器内关闭 UDP GSO。 UDP GSO 在部分容器虚拟网络上会让吞吐量大幅下降，见 tailscale#20858。Tailspace 通过 cgroup 命名空间识别容器环境并关闭 UDP GSO。
  • 不依赖 systemd、init 与 cron。 没有 init 进程的容器不会回收僵尸进程，Tailspace 读取 /proc 状态把僵尸进程当作已退出；即使容器开启了 hostPID: true，Tailspace 也会核对根文件系统，不会误用宿主机的 crond。
  • 共享 PID 命名空间也安全。 进程查找不使用 ps 或 pgrep，只通过 /proc/PID/fd 和 --statedir 识别属于你自己的 tailscaled 和监管进程，不影响同节点其他 Pod。
  • 识别 Pod 重启。 Tailspace 同时记录内核 boot ID 和容器根 overlay 目录。Pod 在保留主机名和持久化 $HOME 的前提下重启后，会被识别为一次重启服务器，下次 kubectl exec 时清除此前的放弃记录。
  • 限制宿主机多核下的 Go 线程数。 在 124 核宿主机上的容器里，GOMAXPROCS=8 把 Tailscale 的线程从 57 降到 14，单次状态检查的 CPU 时间从 57 毫秒降到 15 毫秒。

不用 kubectl port-forward 访问本地端口

在 userspace 模式下，除 22 端口的 Tailscale SSH 和运行了 OpenSSH 时的 2222 端口外，访问 Pod tailnet IP 的任意端口都会转发到容器内的 127.0.0.1。启动 8888 端口的 Jupyter、6006 端口的 TensorBoard 或 8000 端口的本地服务，本机浏览器打开 http://gpu-pod-01:8888 就能访问。

常见问题

在 Kubernetes 或 Docker 里运行 Tailspace 需要 CAP_NET_ADMIN 或 /dev/net/tun 吗？

不需要。Tailspace 始终以 --tun=userspace-networking 运行，不接触内核 TUN 网卡，也不需要任何特权配置。

容器里没有 systemd 也没有 cron，重建后怎么恢复？

Tailspace 会在你的 shell 启动文件里，比如 ~/.bashrc 和 ~/.zshrc，写入一段耗时约 0.9 毫秒的后台 shell 检查。Pod 重启后，你下次 kubectl exec 或打开 shell 就会把监管进程和 Tailscale 拉起来。

如果 Deployment 重建后 Pod 主机名变了怎么办？

Tailspace 按容器自身的系统主机名在 state/HOSTNAME/ 下保存状态，重建后拿到新主机名的 Pod 会被当作新服务器。想跨重建保留状态目录，可以使用 StatefulSet 或固定 spec.hostname，或者用可重复 auth key 再次运行 tailspace install。
