Tailspace / HTTP 代理与切换

Tailscale HTTP 代理与直连切换

Tailscale 只在启动时读取一次代理设置。在中国大陆实验室服务器、企业内网或跑在易断 VPN 上的 HTTP 代理环境里，代理一旦中断，常规的 tailscaled 就会一直离线直到有人手动登录重启 Tailscale。Tailspace 同时监管直连路径和代理路径，哪条断了就切到另一条。

配置

带 HTTP 代理安装与修改

首次安装前先设置 https_proxy，确保安装脚本能下载 Tailspace 与 Tailscale，同时把这个代理保存给代理路径使用：

export https_proxy=http://127.0.0.1:7890
curl -fsSL https://raw.githubusercontent.com/ttttonyhe/tailspace/main/tailspace | bash

之后随时可以更换或取消代理，无需重装：

tailspace set --proxy http://127.0.0.1:7890
tailspace set --proxy none

只支持 http:// 代理。Tailscale 会忽略 ALL_PROXY，并把所有代理都当作 HTTP 代理，即使写成 socks5:// 也一样。Tailspace 只通过环境变量传递代理，不写进命令行参数，避免代理凭据暴露在 /proc/*/cmdline。

切换规则

直连路径与代理路径的切换机制

  • 宽限期Tailscale 离线后，监管进程在直连路径上等 4 分钟留给 Tailscale 自己重连，在代理路径上等 1 分钟再开始探测。
  • 真实握手探测用 tailscale debug ts2021 经对应路径向协调服务器发起全新 Noise 握手。当前路径不通而另一条通时，不等会话结束直接切换。
  • 识别假死如果当前路径连续两次测试都通，Tailscale 却一直离线，监管进程会在同一条路径上重启 Tailscale。
  • 不中断会话的回切切到代理路径后先等 15 分钟，之后每 5 分钟探测一次直连路径。在线且连续两次通过后，等活动会话结束再切回，累计最多等 3 天。若切回后 30 分钟内直连再次中断，等待时间加倍，最长 4 小时。
  • TLS ML-KEM 兼容启动时设 GODEBUG=tlsmlkem=0，防止中间网络丢弃 ML-KEM 密钥交换的 TLS 握手，见 tailscale#20777。
中继加速

把 DERP 中继拉近

服务器位于 hard NAT 后或只能经 HTTP 代理上网时，流量会走中继。运行 tailspace status 可查看活动设备是否标出 relay。有两种 Tailscale 功能可以把中继拉近：

  • 自建 DERP 服务器对两条路径都有效。不需要域名，在附近 VPS 上运行 derper --certmode manual --hostname IP --verify-clients 并同机运行 Tailscale，就能生成证书并只放行你的 tailnet。
  • Peer RelayTailscale 1.86 及以上版本支持用自己的某台设备经 UDP 做中继。HTTP 代理不转发 UDP，只在服务器能直接发出 UDP 时有用。
常见问题

常见问题

为什么 Tailscale 自己不会在代理和直连之间切换？

tailscaled 只在启动时读取一次 https_proxy。Tailspace 用 tailscale debug ts2021 探测直连和代理两条路径，当使用中的路径失效时带着可用环境重启 Tailscale。

Tailscale 支持通过 ALL_PROXY 使用 SOCKS5 代理吗？

不支持。Tailscale 会忽略 ALL_PROXY，并把所有代理当作 HTTP 代理。请使用 Clash 或 Mihomo 等工具的 HTTP 混合端口，以 http://HOST:PORT 传给 Tailspace。

从代理切回直连时会断开我正在用的 SSH 会话吗？

不会。监管进程会检查 SSH 会话、转发到 127.0.0.1 或 ::1 的连接以及 tailscale nc 等 LocalAPI 连接，有会话时推迟切回，最多等 3 天，并且会排除 tailscaled 自身连向本机回环代理的 socket，不会误判成用户会话。
