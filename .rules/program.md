# The tailspace program

## Layout

- The header comment of `tailspace` lists the sections in reading order, and the `# ----` markers delimit them. Put a new function in the section it belongs to, and keep the header list in step with the markers.
- The file must end with the single line `main "$@"; exit`. bash reads a script while it runs it, and with both commands on one line it has read the `exit` before `main` starts, so a file overwritten in place can't feed it new commands. `install_program` replaces the file by rename, which is safe anyway.
- `TAILSPACE_VERSION` is the only version string. `usage()` is the reference for commands and options, and the option tables in `ADVANCED.md` and `ADVANCED.zh-CN.md` mirror it.

## Bash on CentOS 7: bash 4.2, util-linux 2.23

- No `set -e` and no `pipefail`. Probes such as `status_json` and `path_works` fail as a matter of course, and callers test their status explicitly.
- `set -u` is on. bash 4.2 calls an empty `"${array[@]}"` unbound, so test the length first, as `cleanup_tmp` does with `TMP_PATHS`.
- `setsid -f` doesn't exist there. Detach with `setsid ... &`, as `launch_supervisor` does.
- No here-strings, and no here-documents outside `usage()`: bash writes them to a temporary file, which fails when /tmp is full. `proc_field` splits with an array assignment instead.
- Wait on deadlines against `$SECONDS` whenever a single check can block, as `wait_until`, `cycle_daemon` and `stop_pid` do, because one `status_json` can take `PROBE_TIMEOUT` seconds.
- A command substitution in the supervisor holds the lock, and a TERM waits until it finishes: bash keeps fd 9 open in the forked shell, even with `9>&-` on a function inside. Long work runs as a background job that closes the lock first and is awaited with `wait`, as the path tests in `cmd_supervise` do with `(exec 9>&- && pick_path ...) &`.
- A function that sets globals must not run inside `$(...)`, which forks. The EXIT trap doesn't fire in that fork either, which is why `latest_version` deletes its own temporary file.
- Inside `$(...)`, `$BASHPID` is the subshell's PID. Background loops copy it first: `local self="$BASHPID"` in `watch_daemon` and `update_loop`.
- Read `status --json` with `json_string`, `json_bool` and `node_ip`, which match with `[[ =~ ]]`. The first match is the right one, because ipnstate.Status orders Version and BackendState before Self, and Self before ExitNodeStatus and Peer.
- `load_settings` reads `config` with a `read` loop and no forks, because the shell hook calls it at every login.
- `install_hooks` adds the cron job only when `cron_runs` finds a `cron` or `crond` process whose `root_fs` matches ours, and removes it otherwise. With `hostPID`, a pod sees the host's crond, which reads the host's crontabs; with `hidepid`, no daemon is visible, so `cron_runs` assumes one. Keep this scan out of the shell hook, because it reads every process's `comm`.
- `current_boot` drops the options from `root_fs`, which a remount changes within a boot, and keeps only an overlay's `upperdir`, which tells one container from the next.
- `root_fs FILE` reads a mountinfo file and prints the device, the root within it, and the type, source and options of the mount on `/` that no other mount on `/` is stacked on, found by parent ID whatever order mountinfo lists them in; a mount may be its own parent. It leaves out the mount ID, which Linux reuses and which differs between mount namespaces that see the same files, and it keeps the root, without which a container whose `/` is a directory of the host's disk would look like the host.
- `in_container` treats any cgroup namespace other than the initial one, `cgroup:[4026531835]` in `/proc/self/ns/cgroup`, as a container. Kernels before 4.6 have no cgroup namespaces, so the file markers and the cgroup v1 paths stay.

## Process identity

- Containers may share the host's PID namespace, so `ps`, `pgrep` and name matching would find other users' processes. Identify processes by what they hold, from `/proc` only.
- The supervisor opens `state/HOST/lock` for appending as fd 9 and flocks it in `cmd_supervise`. `lock_holders` lists every PID whose `/proc/PID/fd/9` is that file, and `is_supervisor` picks the one that leads its session, with PID equal to SID from `proc_field PID 3`, and has comm `tailspace`.
- tailscaled runs in a session of its own, through `setsid` in `start_daemon`: Tailscale SSH runs commands without a terminal in tailscaled's session, and a user's `nohup` job there must never be swept with the supervisor's.
- tailscaled must never get fd 9: `start_daemon` passes `9>&-`. tailscaled hands open descriptors to the SSH sessions it starts, so an inherited lock would outlive tailscaled and turn session processes into lock holders.
- `daemon_pids` finds tailscaled by comm `tailscaled` plus the argument `--statedir=$STATE_DIR` in `/proc/PID/cmdline`. Its SSH helpers run as `tailscaled be-child ...` and don't match.
- Long-lived children close the lock: `watch_daemon ... 9>&- &`, `update_loop 9>&- &`, the backoff `sleep "$delay" 9>&- &` and the path tests above. `cmd_supervise` calls `supervisor_shutdown` when its loop ends as well, so the updater never outlives the supervisor. The path test writes `path.new` and renames it, so a killed test leaves the recorded path alone. Children of a killed loop or test live on briefly, so they hold no file in the state directory: the sleeps of the watcher and the updater run with output on /dev/null, and so does `grep` in `path_works`. Probes that run `bin/tailscale` can outlive their loop by up to 20 s, so `supervisor_shutdown` sends TERM to what is left in its own session, through `session_pids`; on NFS, a running binary keeps `bin/`. It goes by session, not by binary, because pods on one node that share a home run the same binary. `update_loop` starts `update-worker` with `setsid`, so stopping never kills an update halfway, and the restart worker gets `8>&-`, so it never holds the install lock. On NFS, an open file keeps uninstall from deleting the state directory. A background function with `9>&-` keeps no copy of the lock; only command substitutions do. `launch_supervisor` passes `8>&-`, so the supervisor never holds the install lock that `prefix_busy` tests.
- Locks are taken on files opened for appending, tested with `lock_free`, never on directories: NFS grants exclusive locks only on files open for writing, and flock(1) opens its file read-only.
- `supervisor.pid` only lets `launch_supervisor` skip the `/proc` scan on every new shell, about 9 ms with 1,400 processes. `supervisor_running` re-checks fd 9, session leadership and comm, so a stale or reused PID fails. The lock held by `cmd_supervise` is the real guarantee.
- `proc_pids` reads all of `/proc/PID/stat`, because a process name can hold a newline, and takes the fields after the last `)`. `session_pids` and `open_sessions` go through it.
- `stop_pid` treats zombies as gone through `alive`, because a container without an init never reaps them. `stop_everything` succeeds only once the state lock is free and `daemon_pids` finds no tailscaled, because a killed one exits a moment after SIGKILL. Before signalling a stored child PID, `kill_child` checks `is_child_of`.

## Supervisor protocol

- The watcher ends a tailscaled run with `restart_for REASON MESSAGE`, which writes REASON to `restart-reason` and then stops tailscaled. `cmd_supervise` reads it after `wait`. Reasons: `hung`, `stuck`, `failover`, `failback`, `needs-login`, plus `update`, which `cycle_daemon` writes. A new reason needs a branch in the `case` of `cmd_supervise`.
- An empty reason is a crash. Crashes, `hung` and `stuck` count as failures, and `FAILURE_LIMIT` in a row end the supervisor with `give_up failing`, but never while `prefix_busy`: an install or update is then judging the binaries and will put the old ones back. The watcher creates `online` the first time a run reaches Tailscale, and the supervisor resets the count when it finds that file.
- `stopped` records why Tailspace stopped in its first word: `user` from `cmd_stop` and `cmd_uninstall`, `needs-login` and `failing` from `give_up`, `enroll-failed` from `enroll`. `cmd_supervise` and its loop stop when the file exists, whatever it says, so `mark_stopped` accepts a file that a full disk leaves empty. `stopped_hint` reads the first word and turns it into the text `status` prints. Every change to the file runs under `with_stop_lock`, a flock on `state/HOST/stopped.lock` through fd 6, because `stop`, `start`, `install`, `give_up` and autostart change it from different processes. The lock waits up to `STOP_LOCK_WAIT`, longer than a stop holds it, and every caller checks whether it got it. `cmd_start` and `cmd_stop` hold it for their whole transition, `start_now` and `stop_now`, so that one running at the same time as the other comes entirely before or after it, and `launch_supervisor` closes fd 6 so the supervisor never holds it.
- `give_up` adds `current_boot`, the kernel's boot ID plus a checksum of `root_fs`, as the second word, unless a stop came first, and shuts the supervisor down still holding the stop lock, so a `start` waits instead of finding a supervisor on its way out; a failed `enroll` likewise runs `stop_now enroll-failed` under the lock. `give_up` waits only 2 s for the lock: a stop that holds it has already written `user` and is ending the supervisor, whose TERM trap can't run while `flock` waits in the foreground. `cmd_autostart` deletes a give-up from another boot and starts the supervisor, so a reboot, or a new container, gets another run. `user` and `enroll-failed` carry no boot and hold until `start` or `install`, and so does an empty file or a record without its newline, which a full disk leaves and which can't tell a stop from a give-up.
- `update-worker` returns when its state directory is gone once it holds the prefix lock, because uninstall may have removed the server before. `cmd_install` creates the state directory again after it gets the lock, for the same reason, and keeps the lock through its final restart.
- `rewrite_hook` builds the new startup file in memory and writes it through `cat` before the rename. A loop's status is its last command's, which hid failed writes, and a builtin's redirection doesn't report the error that NFS gives only at close; `cat` does, so a full disk can't swap in a cut-off copy.
- `cmd_uninstall` takes the prefix lock first, waiting up to 300 s for an install or update, whose `update-worker` outlives the supervisor and would write into the prefix again; only then does it write the stop, so that an update can finish restarting Tailscale and the logout still reaches it. Holding the lock, it logs out, stops everything and runs `remove_state`, which renames the state directory with `mv -T` to `state/.removed.PID`, a rename within `state/` that never becomes a copy across filesystems, then deletes every `state/.removed.*`. On NFS, an open file can keep a renamed copy, which the next uninstall deletes. The check for other servers skips dot names, which `main` allows no host, and stops with an error if `find` fails. The last server's uninstall deletes `bin/`, `bin.prev/` and downloads, and stops with an error if any survives or a hook can't be removed, because the hooks and links run Tailspace and `config` and `state/` mark the prefix as its own, and a retry needs them. It deletes `config` and the lock file while holding the lock and closes the lock right after, so on NFS the lock's .nfs copy goes at that close, and deletes the program and the prefix last from `sh`, which replaces bash: bash keeps its script open, and on NFS the open program would stay as a .nfs file. It stops with an error, keeping the state for another try, when a process doesn't stop, the state can't be deleted, or the cron job can't be removed.
- Whoever gets the prefix lock checks `lock_current`, that its fd 8 is still the lock file in place, before writing anything, because uninstall deletes that file while holding it.
- `main` refuses a host name that starts with a dot or holds anything but letters, digits, `.`, `-` and `_`, for every command. It exports the resolved `TAILSPACE_PREFIX`, and `launch_supervisor` passes it through `env -i`, so detached workers never fall back to another installation. `cmd_supervise` checks the stopped file again once it holds the lock, before it records its PID.
- `cron_set` escapes `%` in the program path and in `CRON_MARK`, because cron reads an unescaped `%` as a line break. It removes the crontab with `crontab -r` when nothing else is left in it, so uninstall restores a user who had no crontab. Cronie keeps a copy of a removed crontab in `$XDG_CACHE_HOME/crontab/crontab.bak`; Tailspace leaves it, because it may be the user's own backup.
- `cmd_self_update` installs a download only if it sets `TAILSPACE_VERSION`, ends with `main "$@"; exit` and passes `bash -n`: an empty file passes `bash -n` and runs without error.
- A new supervisor starts from the path recorded in `state/HOST/path`. `pick_path` keeps that path while it passes `path_works`, and returns `direct` when no proxy is saved; only `failover` and `failback` switch without testing.
- `GOMAXPROCS` is exported once in `cmd_supervise`, so tailscaled, the watcher's CLI probes and the updater inherit it.
- `cycle_daemon` returns 0 for a healthy release, 1 for a broken one, and 2 when it can't tell because Tailspace stopped, also during the soak, or no path works. Only 1 writes `bad-version`.
- In userspace mode both ends of every connection over Tailscale live in tailscaled, so a restart cuts them all. Restarts that only improve things wait while `open_sessions` counts any, for at most `SESSION_WAIT_MINUTES`: `watch_daemon` holds a failback, counting only the time between two checks that both held it back, so a flaky direct path neither restarts the count nor adds the time when going back wasn't possible; any probe that doesn't find the node online, because LocalAPI didn't answer, a login is needed or it's offline, clears the streak and pauses the count, because two tests in a row must both run while online, and `update_worker --auto` holds an update whenever the version that would run next, the download or what another server sharing this home put on disk, differs from the running one. It checks before the download, so that the binaries on disk stay the running ones, and again after the download and `keep_previous`'s copy for rollback, right before `swap_release`, because those can take minutes. `keep_previous` stages the copy next to the download, and only `swap_release` moves it into `bin.prev`, which another server sharing this home may still need. `update_waits` returns 0 to wait, 1 when nothing is open and 2 when the wait has run out; it marks the start in `update-waiting` and logs once. While the mark exists, every `update_worker` run looks again in an hour, whatever fails, and `end_wait` removes the mark and touches `update-checked`, so the next check is a day away again. The hourly look goes through `backdate`, which uses `touch -t` in UTC because BusyBox's `touch -d` takes no relative dates and local time repeats an hour when daylight saving ends. The mark goes only once the update goes ahead or has nothing left to do, so a failed download keeps the wait's age; `update_worker` also removes it on the bad version and with auto-update off, `cmd_set` and `cmd_install` when auto-update is off, and `cmd_install` when it installs Tailscale, all through `end_wait`. `update_loop` also runs the worker once the mark is older than `SESSION_WAIT_MINUTES`, which the hourly look could miss by up to an hour; it does so once per wait, so a failing run falls back to the hourly look. `cmd_supervise` keeps it at start but ages `update-checked`, so the update is checked within one `UPDATE_TICK`, while the start has just cut every session; removing it there would let frequent restarts hold an update off for good. Repairs never wait: crashes, `hung`, `stuck`, `failover` and `needs-login`. Neither do `tailspace update`, `restart`, `install` and `set`, which a person runs.
- `open_sessions PID` counts tailscaled's child processes, which are Tailscale SSH sessions; its TCP sockets to exactly 127.0.0.1, `::1` or `::ffff:127.0.0.1` in states that still carry data, ESTABLISHED and both sides of a half-close, which are connections it forwards; and the connected sockets on its LocalAPI socket in `/proc/net/unix`, where an accepted socket shows its listener's path, such as `tailscale nc`. Other unix sockets don't count: on a host with a D-Bus system bus, tailscaled keeps a D-Bus connection open for good, even in userspace mode. The path reaches awk through the environment, because `awk -v` reads backslashes as escapes. It leaves out the exact addresses and port from `proxy_sockets` for the proxy in tailscaled's own environment, which `daemon_proxy` reads from `/proc/PID/environ` and `with_path` sets only on the proxy path, so a proxy saved since tailscaled started doesn't count. Only a proxy on loopback matters, with loopback literals in canonical form, ::1 however written and IPv4-mapped addresses as IPv4, resolved as tailscaled would: localhost as 127.0.0.1 and ::1, IPv4-mapped literals as IPv4, and other names through `getent ahosts` plus `getent hosts`, because `ahosts` drops ::1 where no other IPv6 address exists, each under a 2-second `timeout` so a slow DNS server can't stall the watcher, where tailscaled's control and DERP connections then go; counting them would hold every failback until the cap. `ls` of `/proc/PID/fd` fails now and then while descriptors change, so its status must not gate the tables. An idle `ssh -N` over Tailscale SSH and a serve forward to a unix socket leave no trace and aren't counted. `tailscale status --json` can't replace it: on a userspace node running 1.104.7 it reported no traffic and no handshake for any peer, even one that had carried a Tailscale SSH session.
- `restart_worker` clears the stopped file under the stop lock after it has stopped everything, because the old supervisor may have given up just before.
- `prepare_directories` takes back what a first install created when it can't write the state directory or `config`, so that a retry doesn't find a foreign, half-made prefix.

## Network paths and settings

- `with_path PATH CMD...` replaces the calling shell with CMD in that path's environment. Call it in the background, in a subshell, in a pipeline, or last. Proxies travel in the environment, never in arguments, because every user can read `/proc/PID/cmdline`.
- tailscaled honours only `http://` proxies and ignores `ALL_PROXY`, so `save_proxy` refuses other schemes. An empty `proxy` file records that no proxy is wanted; the caller's proxy variables count only while the file doesn't exist.
- `tailscale debug ts2021` exits 0 even when the handshake fails, so `path_works` greps its output for `did noise handshake`.
- Probes cap curl at `PATH_PROBE_TIMEOUT` through the fourth argument of `download`; only full downloads retry.
- `parse_options` rewrites `--name=value` into two arguments and records every option in `GIVEN`. `cmd_set` applies only the options `given` reports, because hosts that share a home share the saved settings.
- `enroll` repeats the node's current `Hostname` and `AdvertiseTags`, read from `tailscale debug prefs`, on `tailscale up`, which refuses to run on a node that joined before unless every setting that differs from the default is repeated. If it still refuses, with "requires mentioning all", `enroll` points at the command Tailscale printed and writes no `enroll-failed`.
- `publish_openssh` leaves out the 2222 forward only for a listener of this account that 127.0.0.1 reaches, which `own_listener` finds by the UID and address columns of `/proc/net/tcp` and `tcp6`. 0.0.0.0, 127.0.0.1 and their IPv4-mapped forms take IPv4. An IPv6 wildcard listener counts only when 127.0.0.1 answers and no other user's IPv4 listener holds the port, because /proc doesn't show `IPV6_V6ONLY`. Another user's program on 2222 can't take the port, because a `tailscale serve` forward answers before netstack's forwarding to 127.0.0.1.
- `cmd_status` shows the relay tip when `tailscale status` prints `; relay "`, its text for a device connected through DERP, which may follow a note about an exit node.
- `owned_prefix`, a `config` file plus a `state/` directory, decides whether a directory is Tailspace's. `prepare_directories` refuses any other non-empty prefix and writes `config` first, and `cmd_uninstall` refuses to delete from a prefix that fails the test.

## Secrets

- `enroll` hands the auth key to `tailscale up` as `--auth-key=file:<(printf ...)`, a pipe, so it never reaches the disk or a command line. Never pass a key as an argument, and never echo it.
- `prepare_directories` makes the prefix and the state directory mode 700.

## Boundaries

Reviews and changes keep to these. A problem outside them isn't fixed with more machinery.

- One lifecycle command runs at a time on a server: `install`, `uninstall`, `start`, `stop`, `restart`, `set` and `self-update`. Tailspace orders them against what runs without a person: autostart from a login or the cron job, the supervisor and its give-ups, and the daily update. It doesn't order two of them that someone runs at the same moment, such as `uninstall` with `install`, `start` or `set`. Nothing outside the prefix is touched then, and another `uninstall` or `install` sets things right.
- Host names are as RFC 1123 has them, plus underscores. `main` refuses others, because a host name names a directory and dot names in `state/` are Tailspace's.
- The prefix is Tailspace's own: mode 700, and nothing else writes into it or plants links in it.
- Servers that share a home share one `bin` and one `bin.prev`, so a server rolls back only to the version `bin.prev` holds, which another server's updates may have replaced. Rollback copies per server are out of scope.
- A proxy is named by a loopback literal or by a name that resolves to one loopback address. Wildcard addresses such as 0.0.0.0, and names that resolve to several loopback addresses, are out of scope for telling tailscaled's own proxy connections from sessions.
- The failback hold counts within one tailscaled run. A restart for another reason, which cuts every session anyway, starts it over.
- Listeners bound to one network interface are out of scope for `own_listener`, and a proxy named by a host name is told apart from sessions only where `getent` exists; elsewhere its connections hold restarts up to the 3-day limit.
- `open_sessions` sees processes and sockets, not tailscaled's forwarding state, so a restart can still land in the moment between a connection's last byte and its close, or between a Tailscale SSH command's exit and the end of its output. `localhost` as a proxy host counts as both 127.0.0.1 and ::1, whichever the resolver returns.
- Writes, deletions and listings whose failure would leave a server half installed are checked, and the command stops with an error so that a retry finishes the job.

## Tests

- `tests/lib.sh` sources `tailspace` without its last line, so the tests call its functions directly, after it has checked that line and pointed `HOME` and `XDG_CACHE_HOME` into the scratch directory. It unsets `TAILSPACE_PREFIX`, which would point the program at a real installation. It makes `SCRATCH` with `pwd -P`, because `daemon_pids` compares `--statedir=` as text, and exits if `mktemp` fails, because `cd ""` succeeds and the cleanup would delete the current directory. On exit, `clean_scratch` stops the supervisors and tailscaled of each scratch prefix, found by lock and state directory as the program finds them, never by a path in a command line, which an editor showing a test's log also has, and deletes `SCRATCH`; INT and TERM are turned into exits so it runs.
- The tests replace functions of `tailspace` by name, such as `status_json`, `path_works`, `restart_for`, `launch_supervisor` and `stop_everything`. Renaming one of them means updating the tests.
- `tests/watcher.sh` unsets `SECONDS`, which turns it into a plain variable, so only the stubbed `sleep` moves the clock and the expected times are exact. Keep stub variables clear of the watcher's locals `status`, `state`, `path`, `grace` and `failures`. The expected times come from the constants in `tailspace`: failover at 260 s on direct and at 80 s on proxy, failback at 1200 s, stuck at 500 s, needs-login at 140 s, hung at 60 s.
- `tests/supervisor.sh` runs a copy of `tailspace` whose first line names the bash that runs the test and whose `RESTART_DELAY` is 1, so the backoff takes 15 s instead of 75 s.
- `tests/e2e.sh` must never join a tailnet. Its auth key is made up, and the coordination server refuses it within seconds. It also runs `self-update` against files served through `TAILSPACE_SOURCE_URL`: a damaged one, which must be refused, and one with a newer `TAILSPACE_VERSION`, which must be installed even though the reinstall can't log in.
